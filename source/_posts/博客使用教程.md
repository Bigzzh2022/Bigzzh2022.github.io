## 一、博客结构概览

```
myblog/                          # 博客根目录
├── _config.yml                  # Hexo 站点配置文件
├── _config.anzhiyu.yml          # 安知鱼主题配置文件（覆盖主题默认值）
├── package.json                 # Node.js 依赖
├── scaffolds/                   # 文章模板（post/draft/page）
│   └── post.md
├── source/                      # 源文件目录
│   ├── _posts/                  # 文章存放处（Markdown）
│   └── about/                   # "关于"页面等
├── themes/
│   └── anzhiyu/                 # 安知鱼主题源码
├── public/                      # hexo generate 生成的静态站点（构建产物）
└── .gitignore
```

**核心命令：**

```bash
npx hexo new post "文章标题"     # 新建文章
npx hexo new page "页面名"       # 新建页面（如 about）
npx hexo clean                   # 清理缓存
npx hexo generate                # 生成静态站点（输出到 public/）
npx hexo server                  # 本地预览（默认 http://localhost:4000）
npx hexo deploy                  # 部署（需先配置部署插件）
```

## 二、日常写作

### 1. 新建文章

```bash
npx hexo new post "Git使用教程"
```

会生成 `source/_posts/Git使用教程.md`，文件头（front-matter）格式：

```markdown
---
title: Git使用教程
date: 2026-08-16 21:05:09
categories:
  - 开发工具
tags:
  - Git
  - 版本控制
---

正文写在这里，支持标准 Markdown 语法。
```

> **注意**：`categories` 和 `tags` 只需在文章中声明，Hexo 会自动生成对应的分类页和标签页，无需手动创建。

### 2. 图片资源

- 少量图片：放到 `source/images/`，文章中引用 `/images/xxx.png`
- 大量图片：建议使用图床（如 GitHub 仓库 + jsDelivr CDN），避免拖慢站点

### 3. 本地预览

```bash
npx hexo clean && npx hexo generate
npx hexo server
```

浏览器打开 `http://localhost:4000` 即可预览效果。

## 三、安知鱼主题配置详解

安知鱼（AnZhiYu）是一个功能丰富的 Hexo 主题。本站使用的配置全部集中在 `_config.anzhiyu.yml` 中，该文件会**覆盖**主题内置的 `themes/anzhiyu/_config.yml`。

> 主题完整文档：https://docs.anheyu.com/
> 主题仓库：https://github.com/anzhiyu-c/hexo-theme-anzhiyu

### 3.1 主题配置文件

复制主题自带的配置为站点级覆盖配置（已完成的步骤，供参考）：

```bash
cp themes/anzhiyu/_config.yml _config.anzhiyu.yml
```

然后在根目录 `_config.yml` 中启用主题：

```yaml
theme: anzhiyu
language: zh-CN
```

### 3.2 站点基本信息

`_config.yml` 中的关键项：

```yaml
# 站点标题（显示在浏览器标签页和导航栏）
title: Bigzzh's island

# 副标题（显示在浏览器标签页，可留空）
subtitle: "记录与分享"

# 站点描述（SEO 用）
description: "Linux、OpenWrt、WordPress 等技术的踩坑记录与分享"

# 关键词（SEO 用）
keywords: Linux, OpenWrt, WordPress

# 作者名
author: bigzzh

# 语言
language: zh-CN

# 时区
timezone: Asia/Shanghai

# 部署后的站点地址（必填，影响 sitemap、og 标签等）
url: https://bigzzh2022.github.io
```

### 3.3 社交链接 (social)

`_config.anzhiyu.yml` 中配置作者卡片底部和导航的社交图标：

```yaml
social:
  Github: https://github.com/Bigzzh2022 || anzhiyu-icon-github
  博客园: https://www.cnblogs.com/bigzzh || anzhiyu-icon-book-open
```

**格式**：`名称: 链接 || 图标名`

**图标名**从哪里来？主题的图标字体库定义在远程 CDN：

```
https://cdn.jsdelivr.net/npm/anzhiyu-theme-static@1.1.9/icon/ali_iconfont_css.css
```

可用图标前缀为 `anzhiyu-icon-`，常用示例：

| 图标名                       | 说明                 |
| ---------------------------- | -------------------- |
| `anzhiyu-icon-github`        | GitHub               |
| `anzhiyu-icon-bilibili`      | B 站                 |
| `anzhiyu-icon-qq`            | QQ                   |
| `anzhiyu-icon-weibo`         | 微博                 |
| `anzhiyu-icon-rss`           | RSS                  |
| `anzhiyu-icon-book-open`     | 书本（适合博客链接） |
| `anzhiyu-icon-house-chimney` | 首页                 |

> **踩坑记录**：不要凭印象写图标名（如 `anzhiyu-icon-leaf` 就不存在），写错后图标不显示但构建不报错。校验方法是下载上述 CSS 文件后搜索类名是否存在。

### 3.4 作者卡片 (card_author)

首页侧边栏的作者信息卡片：

```yaml
card_author:
  enable: true
  # 卡片内简介（支持 HTML）
  description: Linux、OpenWrt、WordPress 等技术踩坑记录与分享，欢迎交流~
  # 点击作者名跳转的链接
  name_link: /
```

卡片会自动显示：

- 作者头像（`avatar` 配置项或默认图）
- 作者名（来自根目录 `_config.yml` 的 `author`）
- 站点副标题（`subtitle`）
- 社交图标（`social` 配置）

### 3.5 主页打字机副标题 (subtitle)

首页大图下方的循环打字文字：

```yaml
subtitle:
  enable: true # 是否开启
  effect: true # 打字机效果
  startDelay: 300 # 开始前延迟(ms)
  typeSpeed: 150 # 打字速度(ms)
  backSpeed: 50 # 删除速度(ms)
  loop: true # 循环播放
  source: false # 是否调用第三方句子接口（1=一言 2=一句 3=今日诗词）
  sub:
    - 记录技术踩坑与分享
    - Linux / OpenWrt / WordPress
    - Welcome to my island~
```

### 3.6 页脚 (footer)

```yaml
footer:
  owner:
    enable: true
    since: 2024 # 建站年份，显示为 "©2024 - 2026 By bigzzh"
  custom_text: # 自定义文字（可选）
  runtime:
    enable: false # 网站运行时长统计
    launch_time: 04/01/2021 00:00:00 # 上线时间（启用 runtime 时设置）
```

页脚左下角还会显示 `footerBar`（主题内单独配置段）：

```yaml
footerBar:
  enable: true
  authorLink: https://bigzzh2022.github.io # 作者名点击跳转
```

### 3.7 其他常用配置

```yaml
# 头像
avatar:
  img: https://你的图床地址/avatar.png

# 首页信息
banner:
  enable: true # 首页大图横幅

# 侧边栏
aside:
  enable: true

# 文章默认封面
post_default_cover: /img/default_cover.jpg

# 打赏
reward:
  enable: false

# 评论系统（安知鱼支持 waline/twikoo/artalk 等）
comment:
  use: twikoo
  twikoo:
    envId: 你的环境ID
```

## 四、本地 Git 推送到 GitHub

### 4.1 SSH 密钥配置

推荐用 SSH 方式连接 GitHub（免输密码）：

```bash
# 1. 生成密钥（一路回车）
ssh-keygen -t ed25519 -C "你的邮箱"

# 2. 查看公钥并复制
cat ~/.ssh/id_ed25519.pub
# Windows 下：type %USERPROFILE%\.ssh\id_ed25519.pub

# 3. 打开 GitHub → Settings → SSH and GPG keys → New SSH key
#    粘贴公钥保存

# 4. 测试连接
ssh -T git@github.com
# 看到 "Hi 你的用户名!" 即成功
```

### 4.2 初始化与提交

```bash
# 在博客根目录
git init -b main          # 初始化，默认分支名 main

# 查看状态
git status

# 添加并提交
git add .
git commit -m "init: 初始提交"

# 关联远程仓库
git remote add origin git@github.com:用户名/仓库名.git
git remote -v             # 确认远程地址

# 首次推送
git push -u origin main
```

`.gitignore` 需要包含（Hexo 标准）：

```gitignore
node_modules/
public/
db.json
*.log
```

### 4.3 分支策略（源码 + 部署）

本项目采用**双分支**管理：

| 分支       | 内容                                               | 用途              |
| ---------- | -------------------------------------------------- | ----------------- |
| `main`     | 博客源码（`_config.yml`、`source/`、`themes/` 等） | 备份与管理        |
| `gh-pages` | `hexo generate` 生成的 `public/` 构建产物          | GitHub Pages 部署 |

> `gh-pages` 是 GitHub Pages 的约定分支名，推送到该分支后 Pages 服务会自动发布。

### 4.4 部署到 GitHub Pages

#### 前提

- 仓库名形如 `用户名.github.io`（如 `Bigzzh2022.github.io`），站点地址即 `https://用户名.github.io/`
- GitHub 仓库 → Settings → Pages → **Source 选择 "Deploy from a branch" → 分支选 `gh-pages`**

#### 手动部署流程（本项目做法）

```bash
# 1. 在 main 分支上修改源码并提交
git add .
git commit -m "post: 新增文章"
git push origin main

# 2. 重新构建
npx hexo clean && npx hexo generate

# 3. 切到 gh-pages 分支
git checkout gh-pages

# 4. 用最新构建产物替换分支内容
#    （public/ 里的文件复制到分支根目录）
git rm -r . --cached
#    删除旧文件后，将 public/ 内容复制到根目录

# 5. 必须保留 .nojekyll 空文件！
#    防止 GitHub Pages 用 Jekyll 构建导致主题文件丢失
#    创建：type nul > .nojekyll  （Linux: touch .nojekyll）

# 6. 提交并推送
git add .
git commit -m "deploy: 重新构建"
git push origin gh-pages

# 7. 切回源码分支继续开发
git checkout main
```

> **踩坑记录**：忘记 `.nojekyll` 时，GitHub Pages 会用 Jekyll 构建，主题文件会报错（如 "The anzhiyu theme could not be found"）。加上空 `.nojekyll` 文件后即修复。

#### 部署验证

```bash
# 推送后等待 1~2 分钟，然后访问
curl -s -o /dev/null -w "%{http_code}" https://用户名.github.io/
# 返回 200 即部署成功
```

## 五、常见问题

| 问题                          | 解决                                                         |
| ----------------------------- | ------------------------------------------------------------ |
| `npx hexo` 命令提示 pnpm 冲突 | 删除 `node_modules/` 和 `pnpm-lock.yaml`，重新 `npm install` |
| GitHub clone 主题超时         | 用 gitee 镜像，或直接下载 codeload 的 zip 解压到 `themes/`   |
| 图标不显示                    | 图标名错误，校验 `ali_iconfont_css.css` 中的类名             |
| 部署后样式丢失                | 检查 `gh-pages` 分支是否包含 `.nojekyll`                     |
| 推送到 `用户名.github.io` 404 | 仓库名必须与用户名完全一致                                   |
| SSH 连接被拒                  | 公钥未添加到 GitHub，检查 `ssh -T git@github.com`            |
| 修改配置不生效                | 先 `npx hexo clean` 再 `npx hexo generate`                   |
