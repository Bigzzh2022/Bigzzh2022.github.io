图标名从哪里来？主题的图标字体库定义在远程 CDN：

可用图标前缀为 anzhiyu-icon-，常用示例：

图标名 说明
anzhiyu-icon-github GitHub

anzhiyu-icon-weibo 微博
anzhiyu-icon-rss RSS

踩坑记录：不要凭印象写图标名（如 anzhiyu-icon-leaf 就不存在），写错后图标不显示但构建不报错。校验方法是下载上述 CSS 文件后搜索类名是否存在。

4.3 分支策略（源码 + 部署）

本项目采用双分支管理：

分支 内容 用途
main 博客源码（_config.yml、source/、themes/ 等） 备份与管理
gh-pages hexo generate 生成的 public/ 构建产物 GitHub Pages 部署

gh-pages 是 GitHub Pages 的约定分支名，推送到该分支后 Pages 服务会自动发布。

4.4 部署到 GitHub Pages

前提

  • 仓库名形如 用户名.github.io（如 Bigzzh2022.github.io），站点地址即 https://用户名.github.io/
  • GitHub 仓库 → Settings → Pages → Source 选择 “Deploy from a branch” → 分支选 gh-pages

手动部署流程（本项目做法）

踩坑记录：忘记 .nojekyll 时，GitHub Pages 会用 Jekyll 构建，主题文件会报错（如 “The anzhiyu theme could not be found”）。加上空 .nojekyll 文件后即修复。

五、常见问题

问题 解决
npx hexo 命令提示 pnpm 冲突 删除 node_modules/ 和 pnpm-lock.yaml，重新 npm install
GitHub clone 主题超时 用 gitee 镜像，或直接下载 codeload 的 zip 解压到 themes/
图标不显示 图标名错误，校验 ali_iconfont_css.css 中的类名
部署后样式丢失 检查 gh-pages 分支是否包含 .nojekyll
推送到 用户名.github.io 404 仓库名必须与用户名完全一致
SSH 连接被拒 公钥未添加到 GitHub，检查 ssh -T git@github.com
修改配置不生效 先 npx hexo clean 再 npx hexo generate
